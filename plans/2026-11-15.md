**Implementation outline**

1. Document the format-helper contract: append exactly the helper-owned newline to formatted content, define whether existing line terminators are rejected, and define null-format and formatting-failure behavior without silently modifying protocol data.
2. Use a measured formatting approach with vsnprintf and correct va\_copy/va\_end handling when traversing arguments more than once. Allocate enough space for content, newline and terminator, and check size arithmetic and allocation failure.
3. Send the formatted bytes and newline through network\_send\_all, excluding the terminating NUL. Propagate transport failures and release temporary storage on every path.
4. Add independent socketpair receiver tests for empty content, normal numeric/string substitution and content longer than a small stack buffer. Add controlled formatting/allocation or transport failure checks where practical; document other protocol/receive stubs as unfinished.

**Acceptance checks**

- [ ] Receiver bytes exactly equal the formatted content followed by the documented newline, without an embedded trailing NUL or silent truncation.
- [ ] Empty, ordinary and long formatted lines obey the same contract, including the documented policy for input already containing line terminators.
- [ ] A peer failure returns an error through the helper, temporary storage is released on success and failure, and no second incomplete send loop is introduced.
- [ ] Run focused tests and make test on a supported POSIX platform after predecessor work; do not claim the entire backup system or wire-protocol parser is complete.

**Implementation outline**

1. Keep an actual socketpair integration test with a receiver running concurrently. Include a payload larger than normal socket buffers and a bounded timeout so a regression fails instead of hanging.
2. Introduce a narrowly scoped test seam for the send call, leaving the production default as the real syscall. Script a short write, EINTR, and further short writes, capturing requested offsets and byte counts.
3. Add deterministic zero-progress and permanent-error sequences, with an error after partial progress. Assert termination and documented error propagation; do not rely on network timing to provoke these cases.
4. Keep receiver observations independent of sender return values and compare binary bytes exactly. Add peer-disconnect and zero-length checks, clean up descriptors/threads on failure, and run through existing make test and CI without weakening checks.

**Acceptance checks**

- [ ] The scripted sequence proves that offsets advance exactly once for accepted bytes and remain unchanged across EINTR; no bytes are dropped or duplicated.
- [ ] The real receiver obtains a large binary payload exactly, with no socket-buffer deadlock and with a bounded overall test duration.
- [ ] Zero progress, permanent error and disconnected-peer cases fail predictably; a deliberately broken one-send implementation or the current success-only stub fails the relevant tests.
- [ ] The tests are included by the current Makefile discovery, existing checks remain enabled, and actual supported-platform test results are recorded during implementation.

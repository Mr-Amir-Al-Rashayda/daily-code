**Implementation outline**

1. Implement only network\_send\_all, retaining the existing public return convention. Send from a byte pointer advanced by the number actually written; do not assume one send call transfers the full buffer.
2. Handle EINTR without losing progress; treat permanent errors and zero-progress sends as failures rather than success or an infinite loop. Document the blocking-socket assumption and the policy for EAGAIN/EWOULDBLOCK; do not busy-spin.
3. Define zero-length and invalid-argument behavior, including null data with nonzero count. Use a portable, documented approach to prevent SIGPIPE from terminating the process when the peer disconnects.
4. Add one genuine socketpair transfer test with an independent receiver and binary payload. Keep listener, connection, receive and formatted-line stubs explicitly outside the completion claim.

**Acceptance checks**

- [ ] An independent socketpair receiver gets the exact bytes and length, including embedded zero bytes, and the sender reports success only after transferring the complete payload.
- [ ] Zero-length and invalid-argument cases match the documented policy; a zero-progress or permanent send failure terminates with the error convention.
- [ ] A disconnected peer does not cause false success or unexpected SIGPIPE termination. Other networking functions are still documented as unfinished.
- [ ] Run the project build and focused network test on a supported POSIX environment; record actual results separately from this proposal.

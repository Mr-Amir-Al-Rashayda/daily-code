**Implementation outline**

1. Build a small CLI accepting a JSON matrix, solver mode, explicit tolerance and iteration limit. Reuse the proposed validation helper; treat that helper as a prerequisite, not completed work.
2. Emit a documented JSON result with capacity in bits/channel use, final gap in nats, iteration count, selected settings and a convergence flag calculated from the requested tolerance.
3. Define an explicit unconverged outcome when the iteration budget is exhausted. Do not pair a last-updated distribution with bounds calculated for the previous distribution: reevaluate consistently or omit that distribution from the report.
4. Document one BSC and one asymmetric input and add CLI checks for JSON parsing, reproducible numerical output and an intentionally exhausted iteration limit.

**Acceptance checks**

- [ ] A documented command produces parseable JSON without editing Python source or opening a plotting window.
- [ ] BSC crossover 0.1 reports capacity near 0.531004 bits/channel use within a stated numerical tolerance.
- [ ] A deliberately insufficient iteration budget reports unconverged instead of an unconditional success.
- [ ] Reported distributions and bounds describe the same evaluated state, or the output explicitly excludes the distribution.
